How to use this page

This page is a map of where every request goes. Boxes are the parts of the harness; lines are the routes between them. Change the lines and boxes, then press Save.

  1. Follow a request from left to right. It enters at Request (the Interceptor), goes through Compression (tick what should shrink it), then to the Router. The Router scores how hard it is and sends it out of one of its outputs (Strong, Weak, Weak with tools, Weak over a size limit) to a model box. A model box is a name the Gateway serves; inside it, Served by lists the provider models that actually answer.
  2. Change where a route goes by dragging from the dot on the right of an output to a model box. Each output goes to one model, so the new line replaces the old one.
  3. Set fallbacks by dragging a model's If it fails dot to another model. When a model errors, hits a rate limit or times out, the Gateway tries its fallbacks from the top. Reorder them with ↑ ↓, and hover a model to see its fallback lines clearly.
  4. Add a model with Add model above: give it a name, pick where it runs (OpenRouter, Groq, Ollama…) and the model id. For OpenRouter you can search its whole model list in the dialog, filter to free or tool-capable models, and click one to fill in the id. To give an existing model a second provider model, use + Add provider model in its box; the Gateway then shares requests between them.
  5. Remove things: Clear unconnected models removes every model box that no route or fallback line touches in any routing; × in a model's title removes the whole model; × next to a provider model removes just that one; click a line and press Delete (or Remove connection) to remove a route.
  6. Use different routings for different chats. New routing copies the one shown under a new name; change its lines, compression and tools, then Save. In Bright Chat, pick it per chat in Options or per project in its settings, or choose One model directly to skip routing. Model boxes and fallbacks are shared by every routing. Other clients pick one with the header x-harness-profile.
  7. Tools lists the MCP servers from mcp-servers.json. Untick one to stop offering it to the model in chats on this routing.
  8. Save writes each change where it belongs and tells you what it saved. The Router and Interceptor use changes on the next request. Restart the Gateway (LiteLLM) after changing models or fallbacks. Discard changes goes back to what is saved.

Hover over anything on this page for a short hint. With Show live requests on, each request's path lights up green as it goes through. Box positions are kept in this browser; Tidy layout lines them up again.

Save writes the Router's choices to its config file, the Interceptor's to harness-settings.json, and models and fallbacks to config.yaml, keeping its comments. Other classifier settings are on the Settings page.
